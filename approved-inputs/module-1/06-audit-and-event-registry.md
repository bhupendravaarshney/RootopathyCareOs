# Module 1 audit and event registry candidate

**Artifact kind:** `audit-and-event-registry`  
**Status:** `CANDIDATE_FOR_APPROVAL`

**Approval:** Not granted

## Decision baseline

Each governed mutation commits one append-only audit event and, where the table below names an outbox event, one immutable outbox record in the same transaction as state and idempotency. Event names are past tense, lowercase dot-separated, version 1. Migration-owned definitions reject unknown versions, missing required keys, extra keys, wrong subject/aggregate types, and transaction-context drift.

### Common envelope

Audit records contain registry/version, event ID, organization ID, actor type/ID, operation, purpose, subject type/ID, correlation ID, server occurred/recorded times, outcome, reason code or protected reason reference, and payload. Outbox records replace subject with aggregate type/ID and producer operation; consumers never receive session, credential, destination, or provider data.

All payloads permit only the named keys. Common value types are UUID strings, integer revisions, UTC instants, stable state/reason codes, sorted changed-field names, and bounded evidence IDs. Nested objects are prohibited in version 1; arrays are type/bound checked. Free-text reason is never in an outbox event.

### Consumers and delivery

| Consumer                      | Exact subscription and purpose                                                                                                                                |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `m1-readiness-invalidator-v1` | All approved M1 configuration change events; marks matching validation/approval projections stale inside the tenant transaction. No external transport.       |
| `m1-history-projector-v1`     | Configuration submit/decision/activation and entity lifecycle events; builds the minimum-necessary configuration history projection with inbox deduplication. |
| `m1-export-worker-v1`         | `evidence.export.authorized` only; fetches the authorization record under exact service identity and produces one bounded artifact.                           |
| `m1-retention-worker-v1`      | `evidence.export.disposal_requested` only; rechecks legal hold and object digest before disposal evidence.                                                    |

External notifications, analytics, data warehouse, and third-party integration destinations are absent from candidate 1. A persisted event is not permission to publish. Any future consumer needs an exact identity, permission, purpose, schema/version, transport authentication, retention, retry/dead-letter owner, and replay approval.

Audit evidence is retained under the history/export policy. Outbox rows retain delivery evidence for one year after successful delivery and seven years for dead-letter/replay decisions, subject to a longer legal hold. Payload visibility is narrower than source-record visibility and reasons are represented by safe codes/references.

## Verification and acceptance

- Schema tests reject missing/extra keys, wrong type/bounds, nested drift, unknown/retired version, wrong subject/aggregate, context mismatch, and prohibited sensitive fragments.
- Transaction tests prove business/audit/outbox/idempotency atomicity, exact replay, changed replay rejection, concurrency behavior, and rollback.
- Consumer tests prove allow-listed identity/event/version, payload digest, forced RLS, inbox exact-redelivery suppression, changed-content conflict, callback rollback, retry/dead-letter, and governed replay.
- Registry documentation maps every governed operation to its audit/outbox variant and every outbox event to one owner or explicitly no destination.

## Approval boundary

This candidate fixes names and schemas for review but activates no producer, publisher, worker, or consumer. Migration entries must remain disabled in production until the checksum-bound package and destination/operations ownership are approved.
